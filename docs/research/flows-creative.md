# Client flows: creative, events and agencies

What CLIENTS of small creative/event/agency businesses see and do in the tools those businesses use today.
Researched 2026-10-20 from vendor help centers, vendor blogs and review sites (Capterra, Trustpilot, G2).

Evidence labels used below:
- (help) = vendor help-center article, read directly.
- (vendor) = vendor marketing/blog page.
- (review) = third-party review site or blog.
- (inferred) = not confirmed by a source read in this pass.

Coverage note: a three-agent parallel pass was lost when the app crashed, so this pass was redone directly with a
smaller budget. Fully covered: Frame.io, Filestage, Pixieset, ShootProof, HoneyBook, Dubsado, Aisle Planner,
ManyRequests, Assembly, Printavo. NOT covered in this pass (still open): Wipster / Vimeo review, Planning Pod,
Allseated, Productive, Teamwork, Basecamp client access, Moxie, Webflow / Figma share links, ShopVOX.

Intercom image URLs (downloads.intercomcdn.com, intercom-attachments) carry expiring signatures; open the help
article page to get a fresh one. The help article URL is listed first for that reason.

## 1. Frame.io (video review)

### Business types
Video production, post-production, motion/animation studios, agency creative teams, brand in-house video.

### Client flow (Review Link, legacy V3 behaviour; V4 "Shares" keep the same core)
1. **Email or pasted link** from the studio. No account needed to view or comment (help).
2. **Passphrase screen** if the link is protected (help). Invite-only links require the listed email to log in (help).
3. **Asset grid** when several files are shared; click a file to open it. Arrows < > switch between files (help).
4. **Player / viewer screen**
   - Player with play/pause (spacebar), timeline with coloured comment dots (hover shows the comment) (help).
   - **Version stack**: if the file is a stack, the latest version opens first; client can switch versions and
     compare side by side (help, via search summary of the review-page article).
   - **Comment box**: typing pauses the video and pins the comment to the current timecode; a yellow range
     handle on the bar turns it into a range comment; ESC drops the range; checkmark posts without timecode (help).
   - **Paintbrush**: draw shapes/arrows in colours on the frame; does not alter the file (help).
   - First comment by a signed-out client triggers a **name + email prompt** (used for identity and email
     updates). Signed-out clients cannot edit earlier comments after leaving (help).
   - **Comment list (right)**: collapsed by default, opened from the message icon; click a card to jump to its
     frame; circle on a card marks it complete; "Hide" toggles completed; sort by Oldest/Newest/Timecode/Commenter
     (help).
   - **Status control (top right)**, only if enabled: Approved / In Progress / Needs Review. Selecting it
     notifies the project team (help).
   - **Download button (top right)**, only if enabled: original file; "Download All" on multi-asset links opens the
     Transfer app with Original / Highest proxy / Lowest proxy (help).
   - If commenting is disabled the client can only watch and read comments (help).
5. V4 adds anchored comments, attachments, emoji reactions, and drawing in a full-screen view (vendor, V4 page).

### Used most vs ignored / complaints
- Used most: timecoded comments. "clients can leave comments at specific times ... greatly reduced the vague emails
  and phone calls" (review, Capterra https://www.capterra.com/p/148214/Frame-io/reviews).
- Complaint: links began asking clients to create an account where before an email was enough (review, Capterra).
- Complaint: playback defaults to about 560p, so clients ask why the video is "low-quality" (review, Capterra).
- The approval status control is optional and secondary; the comment list is the core (help + inferred).

### Screenshot URLs

- https://downloads.intercomcdn.com/i/o/501216/1cc70e19b6033d4e53c2847c/4703adbdc5d1b4671076447fa36bff7f.png

- Email updates after they give name/email on first comment (replies, new comments on that link) (help).
- New version uploaded to a shared stack: (inferred) email if they are a known reviewer.

## 2. Filestage (review and approval of any file type)

### Business types
Marketing agencies, creative/design agencies, brand teams with external approvers, regulated content (pharma,
finance) where approval trails matter.

### Client flow
1. **Email with a review link** opens straight into the file viewer (help). Reviewers can optionally create a free
   reviewer account to get a dashboard (help).
2. **File viewer**
   - Proof on the right, other reviewers' comments on the left (help).
   - **File gallery strip** at the bottom with every file in the step and its status (help).
   - **Pins**: click anywhere on the file (image, PDF, video, website) to attach a comment (help).
   - **Draw** link under the comment box: drawings, highlights, shapes (help).
   - **Upload attachments** to a comment (logos, swatches) (help).
   - Measurement tools (distance, area), @mentions, sort comments by placement or time, search comments (help).
   - Older versions viewable from the version switcher (help, article title "Viewing older versions & navigating
     through different files").
3. **Review decision buttons**: "Approve Version" and "Request Changes"; admins can also enable "Approve with
   changes" and "Reject" (help).
4. **Reviewer summary** under the comments: each reviewer with a colour dot: green approved, green approved with
   changes, orange requested changes, red rejected, grey not yet reviewed (help).
5. **Reviewer dashboard** (if logged in): project list on the left, external projects at the bottom, and an
   "Awaiting my review" list of files still needing a decision; deciding removes the file from that list (help).
6. Download approved files if the project allows it (help).

### Used most vs ignored / complaints
- Used most: pin comments plus the single Approve / Request changes decision; status colour changes green/orange
  (review, G2 https://www.g2.com/products/filestage).
- The dashboard is only for reviewers who sign up; most clients live in the emailed link (help + inferred).
- Due dates and reminders exist ("Stay on top of your due dates as a reviewer") but were not read in detail.

## 3. Pixieset Client Gallery (photography)

### Business types
Wedding, portrait, family, newborn, boudoir, event and commercial photographers.

### Client flow (from Pixieset-hosted photographer guides plus vendor listing; official help center not reachable)
1. **"Your photos are ready" email** with gallery link (and download PIN if the photographer set one) (review).
2. **Cover page**: full-bleed hero photo, gallery title, date, "View gallery" button (inferred from standard
   template; not read).
3. **Gallery grid**: sets/categories as tabs (e.g. Getting Ready, Ceremony, Reception) (review).
4. **Photo viewer**: heart (favorite), download icon, share, buy/cart icon (review).
5. **Favorites**: first heart asks for an email; the list is stored under that email, so re-entering the email
   restores it; no limit; heart again to remove; "Favorites" option at the top (menu on mobile) (review). Multiple
   named lists possible (inferred). Photographer can export and download favorites (vendor listing).
6. **Download**: enter email + **Download PIN** from the gallery email; choose sets or all; choose size (Full
   resolution / Web size); desktop gets a ZIP; on phone it lands in Files (review).
7. **Store**: prints and products from within the gallery, cart, checkout (vendor listing).
8. **Mobile gallery app** per gallery (inferred; not confirmed this pass).

### Used most vs ignored / complaints
- Used most: favorites (as the selection step for albums/retouching) and full-gallery download.
- Complaint: "sometimes clients have a difficult time downloading the images" (review, Capterra
  https://capterra.com/p/207189/Pixieset/reviews/).
- Trustpilot defenders say most bad reviews come from end clients of photographers who set galleries up wrongly
  (review, https://au.trustpilot.com/review/pixieset.com). End clients do review the platform directly.
- Photographer guides warn clients not to screenshot photos (resolution loss), which shows clients do it (review).

### Screenshot URLs

- https://thislittlelight.mypixieset.com/blog/pixieset-gallery-guide/

(These are photographer-written client guides with screenshots of the real client screens.)

### Notifications to the client
- Gallery delivery email with link and PIN (review).
- Gallery expiry reminders and store promos (inferred; standard across gallery tools, Pixieset-specific doc not
  found this pass).

## 4. ShootProof (photography)

### Business types
Wedding, school/sports/event volume photographers, portrait studios.

### Client flow
1. Gallery email; visitors are identified by email address (help FAQ, via search).
2. **Gallery** with PIN protection option (vendor feature index https://www.shootproof.com/feature-index).
3. **Favorites (star)**: any visitor stars unlimited photos into one Favorites list (vendor blog).
4. **Labels** (the real proofing tool): the photographer makes the client the "Linked Contact" and creates labels
   with limits, e.g. "Album - 40 photos", "Parent album - 15", "Canvas - 3". The client tags photos up to each
   limit; one photo can carry several labels; "View All Labeled Photos" shows each label's list where the client
   can remove or relabel (vendor blog).
5. **Downloads**: can be restricted to the Linked Contact and capped; limited clients see a countdown of remaining
   downloads; gallery-wide per-visitor caps too (help FAQ, via search).
6. **Store / orders, invoices and contracts**: ShootProof also sends client invoices and contracts (vendor feature
   index; client screens not read this pass).

### Used most vs ignored / complaints
- Label limits are the feature photographers promote to make clients finish album picks fast (vendor blog).
- Client complaints not collected this pass.

### Screenshot URLs
- https://www.shootproof.com/blog/labels-help-clients-pick-favorite-photos-fast/
- https://www.shootproof.com/wp-content/uploads/shootproof-labels-favorite-photos-108.jpg
- https://help.shootproof.com/hc/en-us/articles/360062280593-ShootProof-FAQs (403 to bots; open in a browser)

### Notifications to the client
- Gallery email; email marketing for deals and gallery-expiration reminders (vendor blog).

## 5. HoneyBook (client portal for proposals, contracts, invoices)

### Business types
Wedding and event vendors (photographers, planners, florists, DJs), designers, coaches, small creative agencies.

### Client flow
1. **Email from the business** with a file (smart file) or a direct link. Access is **loginless** whenever files or
   emails are sent through HoneyBook (help).
2. **Smart file** (the main thing clients see): one document that chains steps such as service selection,
   scheduling, proposal, contract, invoice and payment (help
   https://help.honeybook.com/en/articles/5949959-commonly-combined-steps-in-smart-files). Contracts can require
   smart fields to be filled before signing; signing is a few clicks (help/vendor). Payment by card or ACH (review).
3. **Client portal / project workspace** tabs (help):
   - **Activity**: when files were sent, email threads, message the business.
   - **Files**: documents, attachments, bookmarks; act on them.
   - **Payments**: invoice files and payment schedule; make upcoming payments.
   - **Meetings**: read-only upcoming and past meetings (no booking from the portal).
   - **Notes**: notes the business shared, read-only.
   - **Project details**: fields the business marked client-visible, read-only.
   - **Attach / Upload** button: client adds images/files; nobody is notified.
   - **All Projects** button to switch projects (repeat clients often land in an old one).

### Used most vs ignored / complaints
- Used most: the smart file (sign + pay in one pass). The portal tabs are secondary (help + inferred).
- HoneyBook went loginless because clients disliked logging in to see a file; older reviews said clients had to
  click a time-sensitive login button (review, https://annawu.com/?p=26962, 2018).
- Trustpilot mentions issues with clients accessing portals (review, https://www.trustpilot.com/review/honeybook.com?page=6).
- Client uploads trigger no notification, so they can be missed (help).

### Screenshot URLs
- https://help.honeybook.com/en/articles/6428603-your-clients-experience-with-the-client-portal (text only)
- https://help.honeybook.com/en/articles/9468125-client-portal-and-access-faqs
- https://www.honeybook.com/blog/how-to-create-a-client-portal (vendor blog with portal images)
(No direct client-screen image URL captured this pass.)

### Notifications to the client
- Email for each file sent (proposal/contract/invoice) with a portal link (help).
- Payment reminders and autopay receipts (inferred; not read this pass).

## 6. Dubsado (client portal)

### Business types
Wedding/event vendors, designers, photographers, coaches, virtual assistants, small agencies.

### Client flow
1. **Client-specific link** from a project email logs the client in by email, no password; the public portal URL
   needs a password. Portals are off by default until the business activates them (help).
2. **Home**: summary of things needing attention: open invoices, incomplete forms, unread emails (review/help
   summary).
3. **Projects**: documents and invoices per project; dropdown to switch projects (review/help summary).
4. **Emails**: read past project email threads; cannot send from here (review).
5. **Profile**: edit own contact details (review).
6. Items shown: invoices, sent forms (questionnaires, proposals, contracts), appointments, project details,
   external links. Tasks, notes and internal fields stay private. Incomplete forms show on Home and Projects;
   completed only on Projects. Password-protected forms open only inside the portal (help).
7. Branding: welcome message, logo, banner, colours; per-client banner override (help).

### Used most vs ignored / complaints
- Clients mostly act from emailed links (sign, pay, fill questionnaire); the portal is the "where is that file"
  fallback (inferred).
- A designer reported a standard questionnaire appearing on every client's portal unnoticed and asked for a "view
  as client" preview (review, featurebase request).
- Reviews focus on setup burden for the business, not client confusion (review, Capterra
  https://capterra.com/p/206389/Dubsado/reviews/).

### Screenshot URLs

- https://help.dubsado.com/en/articles/15920590-customize-the-client-portal
- https://assembly.com/blog/dubsado-client-portal (competitor guide with screenshots)

## 7. Aisle Planner (couple view)

### Business types
Wedding planners and coordinators (they invite couples), venues, and couples planning alone.

### Client (couple) flow
1. **Invite from the planner** (Planning Partners) or self sign-up (help collection "For Couples").
2. **Dashboard**: overall to-do progress percentage, RSVP overview, budget allocated (review, tech.co 2014; current
   layout not confirmed).
3. **Checklist**: one list of done / to do; assign tasks to people; comments/notes per item; due dates; delete
   items; mark complete; download as PDF. Suggested timeframes per task (help + review).
4. **Budget**: tracks payments and invoices synced to vendor records; 30 currencies (help). Payment due-date
   reminders (review, planner quote).
5. **Contact Library / vendors**: info, points of contact, social, notes, payment methods; potential vs booked;
   import from Apple/Google/Outlook; invoice amounts and due dates feed the budget (help).
6. **Guest Manager**: build list, multiple lists (rehearsal, shower, brunch), RSVP tracking, confirmed guests flow
   into seating, exports for addressing, counts and meal selections for the caterer (help).
7. **Simple Seating**, **Design Studio / Inspiration**, **Wedding Website** with online RSVP (help titles, vendor).
8. **Messages** with fiance and planning partners (help title).

### Used most vs ignored / complaints
- Checklist is "intentionally long and comprehensive" (vendor). Reviews are mostly from planners (G2 4.3/21).
- "desktop version works better than mobile" (review roundup via search).

## 8. ManyRequests (productized agency portal)

### Business types
Productized design agencies ("unlimited design"), video editing, content, web dev, SEO/marketing retainers.

### Client flow
1. **Account**: auto-created after card checkout; with bank transfer the client can submit requests only once the
   invoice is PAID. Login at portal/login or custom domain (help).
2. **Dashboard**: welcome message, onboarding content and announcements, counts of open and completed requests,
   request list (help).
3. **Create Request** (top right on every page): pick service (skipped if one), title, service-specific
   questions, brand, optional due date (if allowed); "Save as draft" appears after a title; add-ons trigger a
   checkout first; also "submit via email" (help).
4. **Requests**: list with Drafts tab; open one to comment, upload files and follow progress (help).
5. **Services**: catalog with prices and Purchase (help).
6. **Credits / Hours** balances, **Messages** chat, **Reports** (timesheets, credits), **Invoices** (view,
   download, pay), **Storage** (folders), **Organization** (owner adds colleagues), **Brands**, **Extensions**
   (links/pages) (help).
7. **Settings**: profile, notification preferences, password + 2FA, subscription and billing address (help).
8. Mobile: sidebar behind a menu icon, Create button stays on top (help).

### Used most vs ignored / complaints
- Core loop is Create Request -> request thread -> deliverable files. Reports/Storage are optional modules.
- Client complaints not collected this pass.

### Screenshot URLs
- https://help.manyrequests.com/en/articles/5440247-client-experience-and-client-view (7 screenshots, incl.

- https://help.manyrequests.com/en/articles/9531636-how-can-my-clients-submit-requests (6 screenshots: catalog,

## 10. Printavo (print shop quote and artwork approval)

### Business types
Screen printing, embroidery, DTG/DTF, promo products, sign shops.

### Client flow
1. **Approval link** sent from the quote/invoice Messages tab; quote approval and artwork approval can be requested
   separately (vendor blog, help article title "Requesting Approval").
2. **Approval page**: mockups attached to each line item; clean page on any device where the customer "reviews,
   approves, and pays their deposit" in one step (vendor homepage). **Approve** and **Decline** buttons side by
   side (vendor blog). Customers can request changes to quotes and artwork; those messages land in the shop's
   inbox (vendor blog).
3. **Invoice** with a pay-now link (vendor).
4. Approvals are logged on the job (vendor).

### Used most vs ignored / complaints
- Single-click approve of the mockup is the point; shops automate a 50% deposit request after artwork approval
  (vendor).
- Customer-side complaints not collected this pass. No customer screenshot found.

### Screenshot URLs

## Synthesis: core client views per business type

| Business type | Core views (in order of use) | Evidence |
|---|---|---|
| Video production / post | 1. Review player with timecoded and range comments plus draw-on-frame. 2. Version switcher (v1/v2, compare). 3. One-click status (Approved / Needs changes) and final download. | Frame.io review link; Filestage decisions; Capterra praise of timecoded comments |
| Design / branding / marketing creative | 1. Proof viewer with pin comments and an Approve / Request changes decision. 2. Per-reviewer status (who has and has not decided). 3. "Awaiting my review" list across files. | Filestage viewer, reviewer summary, dashboard |
| Photography | 1. Gallery with sets and favorites (selection with limits per product). 2. Download with size choice (and PIN). 3. Print store / cart. Before the shoot: contract + invoice. | Pixieset, ShootProof labels, HoneyBook/Dubsado |
| Wedding planning / events (couple) | 1. Checklist with due dates and assignees. 2. Budget tied to vendor payments with due-date reminders. 3. Guest list with RSVP and meal counts feeding seating. | Aisle Planner couple articles |
| Wedding / event vendors (single service) | 1. One combined proposal -> contract -> invoice/payment file. 2. Payment schedule. 3. Files and messages. | HoneyBook smart files and portal tabs; Dubsado Home/Projects |
| Productized / retainer agencies | 1. Create Request form per service. 2. Request list with status and per-request thread + files. 3. Invoices / subscription and credit balance. | ManyRequests client view |
| Full-service agencies (general portal) | 1. Messages. 2. Files. 3. Billing + contracts + intake forms. | Assembly |
| Print shops | 1. Mockup approval page with Approve / Decline / request changes. 2. Deposit payment on the same page. 3. Invoice with pay link. | Printavo |

### Cross-tool patterns worth copying
- No account for the client: Frame.io, Filestage, HoneyBook and Dubsado all let the client act from an emailed link
  and only ask name/email at the moment it is needed (first comment, first favorite, download). Forcing account
  creation is a named complaint (Frame.io Capterra review; HoneyBook's 2018 move to loginless).
- The action happens in one document, not in the portal: HoneyBook smart file, Printavo approve-and-pay page.
  The portal is the archive/fallback.
- Decisions are explicit buttons with colour states: Approve / Request changes / (Reject) with green/orange/red/grey
  per reviewer.
- Limits make clients finish: ShootProof label caps (40 album photos) and download countdowns.
- Home = "what needs you": Dubsado Home (open invoices, incomplete forms, unread emails), ManyRequests dashboard
  (open/completed counts), Filestage "Awaiting my review".
